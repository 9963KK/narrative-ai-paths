# 积分交易记录金额显示修复说明

## 问题描述

在积分使用历史中发现了一个显示错误：
- **消费类型**的交易记录显示为正数（如 +1.8），但实际应该显示为负数（如 -1.8）
- **充值类型**的交易记录正确显示为正数（如 +10.0）

这个问题导致用户在查看积分历史时产生困惑，明明是消费积分，却显示为正数。

## 根本原因

问题出现在数据存储层面：

### 1. Supabase函数问题
- `deduct_user_credits` 函数在记录消费交易时，将 `amount` 字段存储为正数
- `admin_add_credits` 函数在处理管理员扣除积分时，统计逻辑不正确

### 2. 本地存储逻辑问题
- `creditService.ts` 中的 `deductCredits` 方法也存在同样问题
- `adminAddCredits` 方法在处理负数时统计不正确

## 修复方案

### 1. 数据库层面修复

**修复 `deduct_user_credits` 函数：**
```sql
-- 消费记录存储为负数
INSERT INTO credit_transactions (
    -- ...
    amount,
    -- ...
) VALUES (
    -- ...
    -credit_amount,  -- 改为负数
    -- ...
);
```

**修复 `admin_add_credits` 函数：**
```sql
-- 根据金额正负性决定交易类型和统计
UPDATE user_credits 
SET 
    total_earned = CASE 
        WHEN credit_amount > 0 THEN total_earned + credit_amount 
        ELSE total_earned 
    END,
    total_spent = CASE 
        WHEN credit_amount < 0 THEN total_spent + ABS(credit_amount) 
        ELSE total_spent 
    END
-- ...

INSERT INTO credit_transactions (
    transaction_type,
    amount,
    description
) VALUES (
    CASE 
        WHEN credit_amount > 0 THEN 'admin_add'
        ELSE 'admin_deduct'
    END,
    credit_amount,  -- 保持原始值
    CASE 
        WHEN credit_amount > 0 THEN '管理员充值积分'
        ELSE '管理员扣除积分'
    END
);
```

### 2. 应用层面修复

**修复 `creditService.ts`：**
```typescript
// 消费记录存储为负数
await this.addTransaction({
    transaction_type: 'spend',
    amount: -amount,  // 改为负数
    // ...
});

// 管理员操作的统计修复
localCredits[targetUserId] = {
    total_earned: amount > 0 ? userCredit.total_earned + amount : userCredit.total_earned,
    total_spent: amount < 0 ? userCredit.total_spent + Math.abs(amount) : userCredit.total_spent,
    // ...
};
```

### 3. 历史数据修复

创建迁移脚本 `sql/12-fix-credit-transaction-amounts.sql`：
```sql
-- 修复现有的消费记录
UPDATE credit_transactions 
SET amount = -ABS(amount)
WHERE transaction_type = 'spend' AND amount > 0;

-- 修复现有的管理员扣除记录
UPDATE credit_transactions 
SET amount = -ABS(amount)
WHERE transaction_type = 'admin_deduct' AND amount > 0;
```
